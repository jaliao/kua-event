## Why

目前後台儀表板的活動卡片只呈現標題、地點、時間與一個「編輯」連結，缺少活動代號與票券發放概況，管理者無法一眼掌握各場次狀態，也沒有直達團體票／早鳥票管理的入口。優化卡片可讓管理者在儀表板就快速辨識場次並進入對應的票務作業。

## What Changes

- **卡片資訊改版**：每張活動卡片呈現「活動代號、活動名稱、活動日期、票券張數」。**不顯示活動地點**（目前無此資訊需求）。
  - 票券張數同時呈現三項：**總張數 / 團體票 / 早鳥票**。
- **卡片操作列**：新增三個入口「編輯 ｜ 團體票 ｜ 早鳥票」。
  - **編輯** → 既有 `/events/[id]/edit`，**僅保留活動基本資料編輯**（移除底部團體票批次區塊）。
  - **團體票** → 獨立頁 `/events/[id]/batches`，**集中所有團體票管理**（建立批次、批次清單、Excel 匯出）。原掛在編輯頁底部的 `BatchSection` 移至此頁；批次仍遵循 additive 原則（不修改既有批次）。
  - **早鳥票** → `/events/[id]/early-bird` 佔位頁。早鳥票名單上傳與 Email 寄發**尚未實作**，本變更僅建立導向與佔位頁面（明確標示未實作），實際功能另開變更。
- **取得票券張數**：資料層新增依 `eventId` 統計票券數的查詢，並依票種分項（總數 / 團體票 / 早鳥票），供卡片顯示。

### Modified Capabilities
- `event-management`: 調整「儀表板提供建立與編輯入口」相關需求 —— 卡片呈現欄位（代號、名稱、日期、地點、票券張數）與操作入口（編輯／團體票／早鳥票）改版；團體票批次管理由編輯頁移至獨立頁。

## Impact

- **`app/(admin)/page.tsx`**：卡片版面改版（新增代號、票券張數、三個操作入口）。
- **`lib/data/events.ts`**：`getEvents` 帶入各活動票券數，並依票種分項（總數 / 團體票 / 早鳥票）。
- **`app/(admin)/events/[id]/batches/page.tsx`**（新增）：團體票批次獨立頁，承載既有 `BatchSection`。
- **`app/(admin)/events/[id]/edit/page.tsx`**：移除底部 `BatchSection`（移至團體票頁）。
- **`app/(admin)/events/[id]/early-bird/page.tsx`**（新增）：早鳥票佔位頁（標示未實作）。
- **不影響**：公開票券頁 `/t/[token]`、認證、序號與批次建立邏輯。

## 已確認決策

1. 卡片不顯示活動地點（目前無此資訊需求）。
2. 票券張數呈現「總張數 / 團體票 / 早鳥票」三項。
3. 團體票所有操作（建立批次、清單、匯出）集中於獨立頁 `/events/[id]/batches`；編輯頁僅保留活動基本資料編輯（移除底部批次區塊）。
4. 「早鳥票」入口先做佔位頁，流程未實作。
